# 领域资料

智慧交通、电网巡检和算力项目在当地保留原始数据，平台只交换需求基线、环境说明、数据 *摘要*、系统版本、适用声明与签名验收结果。

## 数据边界

外部主体使用不含真实身份信息的引用编号。交换时间采用带偏移量的 ISO 8601 字符串。原始出行（及其他业务）记录永不进入平台；数据与证据材料只保存：

- 受控引用编号（`dataset_ref` / `storage_ref`）；
- `sha256` 摘要（64 位十六进制）；
- 行数、抽象字段说明等统计性元数据；
- 签名算法、签名值与被签名载荷的摘要。

`contracts/entities.json` 中的字段名称与端点属于稳定接口约定，运行时数据文件位置由 `DATABASE_PATH` 决定。

## 参与方与角色

- `local_institution`（当地机构）：登记项目、需求基线、环境说明（语言/网络/基础设施）、数据摘要；
- `supplier`（供应方）：登记系统版本（`revision` 必须严格递增）与适用声明；
- 双方均可登记里程碑与指标、确认指标、开轮、提交结论与证据摘要。

项目有独立名册（`project_participants`），只有名册内参与方能看到项目明细与证据摘要。

## 验收状态机

1. 里程碑必须归入四个互斥阶段之一：`demonstration`（展品）、`pilot`（试点）、`deployment`（部署）、`formal_acceptance`（正式验收）。
2. 指标经当地机构与供应方**双方确认**后（每个指标有两种角色的确认记录），才允许开启验收轮次。
3. 每个里程碑同时最多有一个 `open` 轮次；提交结论后轮次关闭为 `passed` 或 `failed`。
4. **失败重测另开轮次**：`round_no` 递增，历史轮次与结论永久保留。
5. **版本升级作废未完成验收**：供应方登记更高 `revision` 时，该项目所有 `open` 轮次立即变为 `superseded`，必须针对新版本重新开轮。
6. 结论判定：实测值必须恰好覆盖全部约定指标，按 `gte`/`lte`/`eq` 自动判定。
   - `pass` 必须附当地机构与供应方**双方签名**；
   - `fail` 允许零签名或单方签名。

## 组合视图

`GET /portfolio/combo` 把当前参与方可见的里程碑分列到展品/试点/部署/正式验收四栏。展品或试点即使通过也**不**计为正式交付：`formally_accepted` 只对处于 `formal_acceptance` 阶段且存在 `passed` 轮次的里程碑为真。
